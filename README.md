# smartBidding

Vue 3 + Vant 前端，FastAPI + SQLite 后端，LangGraph 编排合同章节生成。

## 启动

首次启动前，将 `backend/.env.example` 复制为 `backend/.env`，并在其中填写 `DASHSCOPE_API_KEY`。示例文件已配置 Philips Zscaler 代理地址；可按网络环境调整 `DASHSCOPE_PROXY`。该本地配置文件不会提交到 Git。然后在根目录运行下面命令；启动脚本会自动创建后端虚拟环境并安装前后端依赖。

```powershell
python start.py
```

Web 页面访问 `http://localhost:5173`，API 文档访问 `http://localhost:8000/docs`。按 `Ctrl+C` 会同时停止前后端。首次注册一个用户即可使用。

## 当前能力

- 注册、登录、合同项目列表和项目详情
- 输入需求后由 LangGraph 拆章节计划，逐章生成、自查及全文汇总
- 上传标书和参考文档，按标书拆分阶段并将对应原文、参考文本关联到每个阶段
- 新增自定义阶段、编辑阶段标题、折叠阶段和拖动调整顺序；全文重生成时沿用当前阶段计划
- 章节状态、检查结果、提示词调整和单章重新生成
- 停止并继续流程、重试单个阶段、重启全部流程
- 完整生成、历史版本留存与 DOCX 导出

创建合同支持 DOCX、可提取文本的 PDF、TXT 和 MD 文件；扫描版 PDF 暂不支持 OCR。
上传时提取的标书和参考文档正文保存在 SQLite 合同记录中；每个阶段对应的标书摘录和参考摘录保存在阶段记录中。后续重生成直接复用数据库里的文本与阶段内容，不会重新读取上传文件。

这是用于本地演示的基础版本。SQLite 文件默认保存在 `backend/data/contracts.db`。规划、章节起草和章节自查只使用 `DASHSCOPE_BASE_URL` 配置的 Philips AI Gateway Chat Completions 地址；遇到 502、503、504 或无响应时，会在同一地址自动重试，最多请求 3 次。重试状态会显示在 LangGraph 推理过程里。全部章节完成后，系统按计划顺序直接拼接章节标题和正文，不再调用模型做全文合并。项目不会在网关未配置时回退到本地模拟文本。

## 为什么按阶段生成能避免“提示词地狱”

把所有合同要求、例外、参考文风和检查规则不断塞进一个越来越长的总提示词，会让规则彼此干扰，也很难判断某次生成为什么偏离要求。smartBidding 先把标书和用户要求拆成有边界的阶段计划，再为每个阶段分别保存知识点、生成计划、检查标准、对应的标书摘录、参考文本和默认提示词。这样每条指令只作用于相关阶段，用户可以单独调整该阶段的提示词或模型、重试单个节点，并通过自查结果和历史版本定位问题。LangGraph 只在阶段节点完成后汇总全文；新增或修改一条阶段规则不需要把它层层追加到全局提示词中，也不必重写其他阶段的规则，因此提示词保持短、职责清楚且便于维护。
